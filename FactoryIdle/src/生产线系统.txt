根据需求分析和现有代码基础，实现生产线与CPU机制可分为以下7个阶段，共25个步骤：

第一阶段：生产线基础管理
    完善生产线元数据
    确保 sheng_chan_xian_xi_tong.js 中每条生产线包含 id、名称、目标物品ID、绑定核心索引、状态 字段。

    实现创建生产线

    UI 添加“新建生产线”按钮。

    调用 store 方法生成唯一 lineId（如 line_${Date.now()}_${random}），初始化配方分配中该线的空对象，并存入元数据。

    实现删除生产线

    遍历该生产线所有配方分配，通过 建筑调度.尝试减少分配 将机器退回库存。

    删除元数据中对应条目，并从配方分配中移除该线数据。

    实现重命名生产线
    直接更新元数据的 名称 字段。

第二阶段：CPU核心与负载限制
    调整CPU物品配置
    在 pei_zhi_shu_ju.js 的CPU物品中添加 核心数 和 单核频率（或 总频率），例如：

    javascript
    基础CPU: { 核心数: 1, 频率: 1024, ... }
    双核CPU: { 核心数: 2, 频率: 2048, ... } // 频率为单核频率
    计算机系统提供核心信息
    在 ji_suan_ji_xi_tong.js 增加 getter：

    当前核心数(cid)：返回已安装CPU的核心数。

    单核频率(cid, 核心索引)：返回指定核心的可用算力上限（单位：字节）。

    生产线绑定核心

    创建生产线时，自动分配一个空闲核心（核心索引从0开始）。

    提供切换核心的功能（可选）。

    实现生产线负载计算
    在 suan_li_jian_kong.js 中完善 计算生产线负载，遍历该线所有运行中的机器，累加其字节数。

    增加分配时的负载校验
    修改 建筑调度.尝试增加分配，调用 校验能否塞入机器（检查新增机器后负载 ≤ 单核频率）。

    状态切换触发负载更新
    当机器从“运行”切为“停止”（或反之）时，重新计算负载，并可能触发 UI 更新。

第三阶段：生产线视图与筛选
    添加生产线选择器
    在物品概览（wu_pin_lan.vue）顶部增加下拉框，列出所有生产线（包括 default 线）。

    物品列表按生产线过滤
    修改 分组后的物品列表 计算属性：若选中某生产线，则只显示该生产线配方中涉及的物品（通过遍历该线的配方分配获得物品ID集合）。

    配方分配支持生产线选择
    在 pei_fang_ka_pian.vue 的每个机器配置项旁，增加生产线下拉选择，允许将机器分配到指定生产线（默认为当前选中的生产线或 default）。

    科技面板按生产线过滤
    在 ke_ji_lan.vue 的实验室分配区域，增加类似筛选，仅显示当前生产线相关的实验室分配。

第四阶段：最终产物追溯
    实现上游物品递归函数（已有）
    复用 wu_pin_lan.vue 中的 获取所有上游物品ID。

    生产线设置目标物品
    在生产线详情界面，允许用户选择或输入目标物品ID，保存到元数据的 目标物品ID。

    高亮上游链
    当目标物品设置后，在物品概览中高亮显示该物品及其所有上游物品（例如通过边框颜色或图标）。

    自动分配辅助（可选）
    提供“自动分配”按钮，根据目标物品的上游配方，尝试将所需机器分配到当前生产线（需校验库存和容量）。

第五阶段：蓝图导出/导入
    导出生产线蓝图

    提取该生产线的配方分配数据（配方id、建筑id、数量、状态）和元数据（名称、目标物品ID）。

    序列化为 JSON，并用 btoa(encodeURIComponent(...)) 编码为字符串，提供复制按钮。

    导入生产线蓝图

    解析字符串，恢复蓝图对象。

    在当前殖民地创建新生产线（若名称冲突则自动加后缀）。

    遍历蓝图中的分配项，调用 建筑调度.尝试增加分配 逐项分配（通过内存和负载校验，失败项给出提示并跳过）。

第六阶段：CPU热插拔与动态调整
    更换CPU时的核心数校验
    在 尝试安装CPU 和 尝试卸载CPU 中，检查新CPU核心数是否小于已创建生产线数（不含 default）。

    若小于，自动将超出的生产线状态设为“停止”，并提示用户手动调整。

    频率变化时的负载重校验
    当CPU频率因科技升级或更换改变时，遍历所有生产线，若负载超过新频率，自动暂停该生产线，并记录日志/提示。

第七阶段：测试与优化
    单元/集成测试
    确保生产线功能不影响原有速率计算（速率结算仍基于所有生产线总和）。

    性能优化

    缓存生产线负载，避免重复计算。

    优化物品列表过滤逻辑，减少遍历次数。

    完善UI反馈

    增加负载进度条（n-progress）显示每条生产线的占用率。

    操作失败时使用 message 提示具体原因（如容量不足、库存不够）。
